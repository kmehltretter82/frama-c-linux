\chapter{Region User's Guide}
\label{region-plugin}

The \FramaC/\Region computes a single \emph{memory map} for every
\textsf{C}-function in the source. The computation of memory maps is performed
on-demand through \textsf{Ivette} or through the \textsf{API} or once and for
all functions by using the \verb$-region$ command-line option.

The console output generated by the \verb$-region$ is test-oriented and might be
difficult to read by normal users. It consists of a text-based dump of all
regions for all functions with their attributes and properties.

Region maps are visual and interactive data that deserves a graphical user
interface to be exploited. Hence, the recommended way of using \FramaC/\Region
is \emph{via} \textsf{Ivette} and its \textsf{Region Analysis} component:

\begin{logs}
> ivette -region *.c
\end{logs}

The Region Analysis view shows the \emph{memory map} associated with the
currently selected function. You can pin the current map if you want to consult
other functions while keeping the current map visible. You can also download the
current memory map in DOT/Graphviz\footnote{\url{https://graphviz.org}} format.

The currently selected l-value (eg. from the AST
view) and the currently selected region (eg. after clicking in a region) are
highlighted in blue. For the currently selected \emph{region}, the access list
is reported with their respective types and source, which can be clicked to be
localized inside the code.

\begin{center}
\fbox{\includegraphics[width=10cm]{images/ivette-region.png}}
\end{center}

The User's Guide Section is structured as follows:
\begin{itemize}
  \item Section~\ref{region-navigation} explains how to read and navigate
    through the different regions of memory maps.
  \item Section~\ref{region-annotations} explains how to write \acsl
    \emph{region annotations} in order to refine the memory maps.
  \item Section~\ref{region-commands} explains how to use the command-line
    options to generate the \emph{map side-conditions}.
\end{itemize}


\section{Navigating through the Region Map}
\label{region-navigation}

For each function, the \FramaC/\Region plugin generates a single \emph{region
map}. A region map is defined as a graph (acyclic when no pointer is involved)
whose paths start with program variables represented as labels.

\subsection{Region definition}

In any region map, each region is characterized by (at least) its size,
its content, and the memory accesses.
Memory access kinds are: read \texttt{R}, write \texttt{W}, shift
\texttt{S}, and initialization \texttt{I}. Each access is paired with a C type
that defines the size of all memory locations included in the region.

\subsubsection{Arithmetic regions}

Shown in Table \ref{table-region-navigation-primitive}, primitive regions
are defined as region which only include accesses paired with primitive
C types, which are represented as
\texttt{i} for \texttt{int}, \texttt{s} for \texttt{short},
\texttt{d} for \texttt{double}, \texttt{f} for \texttt{float},
 \texttt{b} for \texttt{bool}, and lastly \texttt{x} for multiple
 heterogeneous accesses.

\subsubsection{Pointer regions}
