\section{Alias and shape analysis}
\label{sec-region-alias-shape-analysis}

The region map analysis is based on the creation of simple region and then
merges each simple region with relevant ones to build more complex regions.


\begin{itemize}
    \item modular
    \item over-approximation
    \item flow-insensitive analysis
    \item field/shape analysis
    \item type access analysis (for heterogenous access analysis)
\end{itemize}

\subsection{Modularity}

The \Region plugin generates a region map for each declared function in the
analysis scope.

\subsection{Flow-insensitive}

For the region map generation, statements in conditional branches are analysed
in the same way as if they were sequential.

This behavior may result into an over-approximation of alias analysis and
unecessary region merges would be avoided when taking into account a deeper
control flow analysis. Yet, the development choice is to provide a simple and
quick region analysis.

\subsection{Shape analysis}
\label{subsec-region-shape-analysis}

The region map is dependent on the machine it is analysed for. For instance,
the same C code will not produce the same region map for two different machdep
where an \texttt{int} is either 32-bits or 16-bits.

\subsubsection{Size analysis}

A region is caracterized by its size which is defined as the biggest size
from which each memory locations' size is a multiple of.

Examples:
\begin{itemize}
    \item Compound region: its size is equal to the overall size of the
    full structure (with possible paddings).
    \item Primitive region with only one C type access: its size is equal to
    the size of the C type.
    \item Pointer region (non-garbled): its size is equal to the size of adresses.
    \item Garbled primitive region: its size is equal to the GCD of all accesses' C type size.
\end{itemize}

\subsubsection{Different sizes merge}

A region is a collection of memory locations. The size of a region is defined
as the greater size of elementary memory blocks necessary to represent all the
memory locations contained in the region. If a memory location has a strictly
greater size than the region size, then this memory location is represented by
an array to correspond to the memory location size.
Each region is caracterized by a size which is definied as the GCD among
all the sizes of the memory locations it includes. A merge of two regions
with different sizes will result into a region that includes a set of
elementary memory blocks of smaller size so that each previous memory location
are now represented as a multiple of the merged elementary memory blocks.

For instance, a region of size 160 bits (e.g. a structure with five 32-bits
\texttt{int}) that is also accessed using a 16-bits \texttt{short} pointer will
degenerate into a garbled primitive region of size 16-bits.

    int a, b, c[4];
