This chapter provides complementary information about the graphical user
interface, as seen by an \Eva{} user. Most of the documentation is available
in the graphical interface itself.

\section{A general view of the GUI}

The \FramaC graphical user interface is currently best suited as a
{\em viewer} for analysis results. The typical use case is:

\begin{enumerate}
\item Run \FramaC in the command line and save the result
(option \texttt{-save proj.sav}) to a session file;
\item Open the GUI with \texttt{-load proj.sav} to load the saved session and
explore the analysis results interactively.
\end{enumerate}

The \FramaC GUI is not an IDE (e.g.~you cannot edit code with it), and the
set of available controls in the interface does not include all command-line
options. It is nevertheless very useful for academic examples and tutorials,
in which case it can obviate the need for the command line.

For large and industrial analyses, we suggest considering the GUI as a
complement, but not a full replacement, for the command-line interface.
Using a Makefile or script to parametrize and run the analysis ensures
reproducibility and helps iterative development.

\section{Eva-Related Views, Components, and Sidebar}

The \FramaC GUI is very rich and serves several other plug-ins and analyses.
The following elements are either related directly to \Eva{}, or often useful
for navigation and code comprehension of \Eva{}-related properties:

\subsection{Views}

A {\em View} is a predefined arrangement of related components.

\begin{description}
\item[Eva Summary]: useful first stop for getting an overview of the
analysis. It includes a textual summary, coverage information, list of
messages, and profiling information (Eva Flamegraph).
\item[Eva Values]: the bread and butter of inspecting alarms in the GUI:
AST, Inspector and Eva Values components enable following an alarm from its
manifestation towards its root causes.
\item[Eva Mthread]: for inspection of \mthread-related analyses.
\item[Dive Dataflow]: the Dive plug-in presents graphical illustrations of
dependencies between memory locations.
\item[Properties]: not directly \Eva{}-related, but useful to browse the
list of alarms found by \Eva{}.
\end{description}

\subsection{Components}

The {\em Eva Summary}, {\em Eva Values} and {\em Eva Mthread} components
are related to the views which contain them.
{\em Eva Coverage} and {\em Eva Flamegraph} are also included in the
{\em Eva Summary} view.

Other components which are often useful for \Eva{} analyses:

\begin{description}
\item[Inspector]: presents syntactical information about the current expression
in the AST.
\item[Locations]: when triggered by e.g. Studia (Select reads/writes), lists
relevant locations, for quick navigation.
\end{description}

\subsection{Sidebar}

\Eva{} has its own sidebar in the \FramaC GUI. It allows running, stopping and
restarting an analysis directly from the GUI. The most common analysis
parameters can be modified from this sidebar. As mentioned before, this is
especially useful for simple tests and quick comparisons, but for large,
longer analyses, we recommend using a Makefile or a script to ensure
reproducibility.

Another sidebar related to \Eva{} is the {\em Taints} sidebar, which is filled
when the {\em taints} abstract domain (Section~\ref{sec:taint}) is enabled, and
allows toggling syntactic highlighting of each taint in the analysis.

For \mthread analyses, the {\em Projects} sidebar is also useful, since each
thread is analyzed in a different project.
